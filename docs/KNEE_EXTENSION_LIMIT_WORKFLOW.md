# drive4 主动膝关节：伸直端限位

更新：2026-11-22。目标由操作者确认：膝关节可弯曲、可回伸，但不能越过伸直位置反关节；计划使能drive4主动控制。这里定义的是角度区间，不是把某个旋转方向永久禁用。

当前状态：已核对资料，并收到操作者现场反馈：drive4已使能，`6061=8`、`607F=10000`、`3C18=0`，机械臂已与小腿分开，手推仍困难。助手未连接设备或写入驱动。当前仍是CSP位置模式，尚未确认进入厂家输出端力矩闭环模式；具体限位数值待本次零位、单位、方向和主站控制方式确认。

## 依据与适用范围

主要依据为资料包`ezyZip.zip`内的`01_说明书/TCHL_ECat协议说明书V2.0.8.pdf`，不是整理稿或历史模型对话。原资料包SHA256：`552c9a52451eb4129082c78ba73875f5e3f973da0c6820fdb21b10641eba58bd`；原协议PDF的SHA256：`e012b9f80892ef48909a02c2acaf2439a18fcbd268da7122dc506a93aace0fab`。

核对章节：6.4全闭环模式（PDF第28页，印刷21页）、6.6软限位设置（PDF第30页，印刷23页）、6.7强制抱闸打开（PDF第31页，印刷24页）、0x607D对象表（PDF第88页，印刷81页）及参数地址表。具体固件与drive4型号仍需在线核对。

手册说明EtherCAT控制各模式具有驱动软限位功能；“上位机控制不具备软限位功能”是手册对其控制方式的区分，不能据此认为TwinCAT经EtherCAT也不支持。驱动软限位和TwinCAT主站内的指令限幅应分别配置与验证。

## 三层限制各解决什么

1. **机械伸展止挡**：在真实伸直端阻止机构继续超伸，作为驱动失能、断电或参数失效时的实际边界。其结构、承载和缓冲需按真实夹具与机械臂外力确认。
2. **驱动软件位置上下限**：drive4使能、正确控制模式与坐标成立时，限制其运动指令/位置范围。手册描述超限后零速停车，仍保持使能，随后允许向范围内退回。
3. **主站目标限幅与协调**：TwinCAT生成的目标应在到达驱动极限之前收住，考虑制动距离、刷新延迟和标定误差；与机械臂的运动也必须兼容。

驱动未使能、抱闸强制打开而由外力拖动时，不能把软件位置上下限当成物理止挡。重新抱闸通常会限制双向运动，也不是允许正常屈伸的角度边界。

## 第二步：复核真实伸直位置与计数方向

膝关节伸直定义为本次安装中大腿与小腿的机械参考对齐，不是把驱动当前计数直接当成0。先让膝驱动在有机械支撑、解除机械臂刚性牵制或采用已验证协调控制的条件下独立调试；不能让机械臂位置控制与膝位置控制互相顶住。

记录真实伸直附近参考的`0x6064`，记为`P0`；在已确认可手动/受控活动的范围内，核对小幅屈曲时计数是增加还是减少。顺/逆时针依观察侧而变，设置上下限以计数方向和实际屈伸为依据。

同一控制模式、编码器选择、原点偏移和单位下，取得每度对应的位置单位`C`。全闭环与非全闭环的单位不同：不能照抄手册81或101减速比例子，也不能直接把角度值0和120写入位置单位的607D。

现有仓库使用旧公式：

```text
theta_knee_deg = (axis4_position_raw + 2615016.5409129467) / 36794.035628458296
```

该旧扫描只覆盖0～60°，存在独立测角误差，不能作为“不反关节”的精确零位证明。当前配置`calibration.knee.safe_min_deg=-10`还允许软件计算的负角度；11月22日静止计数约−2896981，按旧式算为约−7.66°。这不证明实物已经超伸，也不能据此直接把某个旧计数写成伸直限位。

本次先记录与核实`P0`，不擅自写回零参数、改变原点偏移、翻转电机方向或重置多圈编码器；这些操作会影响已有坐标与主站目标。

## 第三步：算出边界，再设置驱动与主站

定义本次允许的最小屈曲角为`theta_min`，最大屈曲角为`theta_max`。伸直端应按实测停止距离、延迟和标定误差保留余量；驱动停车不是瞬间完成，不能把在精确0°才触发停车当作不会越界的保证。最大角度也需由真实安装核实，不默认沿用145°。

若已核实屈曲时计数增大：

```text
607D:01 = P0 + C * theta_min
607D:02 = P0 + C * theta_max
```

若屈曲时计数减小：

```text
607D:01 = P0 - C * theta_max
607D:02 = P0 - C * theta_min
```

结果使用驱动认可的有符号32位位置单位；取整应向允许范围内收紧，保证最小值小于最大值。`−2147483648 / 2147483647`这组默认极值表示软限位无效，不能当作已经开启了有效膝角限制。

在参数与主站控制审查完成后，按该驱动版本的流程设置`607D:01/02`并将`Pr8.09`置1，同时在主站限制目标。手册第6.6节称开关默认1，附录参数表又列0，因此必须读取实际值，不能依赖默认开启。若主站有启动SDO或NC软件限位，同步检查实际生效值与单位；保存/重启后的持久性按该设备流程确认并回读，不猜保存命令。

手册`Pr1.19 / 0x3113`为超程保护减速时间，示例默认50ms。这里不改其值，也不把50ms当成整套系统的已测停车时间。不要以单向力矩限制或方向翻转替代角度限位。

## 第四步：先验证边界功能，再做完整动作

最初在远离真实伸直端的小范围测试边界，以已确认的低速、有限力矩和正确目标同步核对：趋近边界时能停止，向范围内部仍能回退，实际位置与警告变化符合预期。先得到真实停止距离与坐标依据，再逐步确定伸直端边界；不通过主动超伸实物来验证软件是否有效。

手册第6.6节描述正/负限位触发时显示`-pot- / -not-`，错误码示例`0x0107 / 0x0108`；其他故障表还列有目标超限与实际超程的不同编码。因此现场记录真实模式、位置、目标、状态字和完整错误文本，不仅凭某个码猜行为，也不屏蔽错误检查让试验继续。

机械臂与小腿刚性连接时，后续必须采用几何兼容的位置/朝向与膝关节运动协调；原空载固定朝向轨迹不能因设置了膝软限位就直接恢复运行。

## 与当前代码的关系

当前配置和`lab_session._passive_leg_guard`按被动假腿编写，要求驱动未使能；drive4使能后会触发停止。这是协议不匹配，不能只改一个`expected_operation_enabled=true`就把主动方案当成已审核。

主动膝方案需要独立记录控制模式、目标生成与限幅、使能过渡、停止方式、设备限位回读和安装标定，再增加相应采集/守卫支持。主动膝输出也会改变机器人所测负荷，论文实验条件需明确区分。当前只读采集、90秒空载曲线和被动保护配置保留，不提供未审查的驱动写入或使能脚本。

## 现场问题：使能后把3C18设0，仍推不动

本次已确认实际模式`6061=8`，属于CSP位置控制，位置环会抵抗偏离目标位置的外力。`3C18=0`不解除位置环，`607F=10000`也只是速度上限，不会切换控制模式。机械臂已分开，当前没有它的刚性牵制。

协议第6.10节（PDF第33页，印刷26页）描述厂家输出端力矩闭环模式：请求模式`6060=-1`，目标为`3C18`（FLOAT，Nm），反馈为`3C1A`，使用`3C04/05/06`力矩环PID增益，并有`607F`速度限制。当前实际模式应以`6061`核实；有符号−1也可能以字节`0xFF`显示。

标准CST模式则是10，目标为6071，不能把两种力矩环的目标和单位混用。零电机转矩、零输出传感器转矩及可低阻力手推也不等同；减速机摩擦、环路参数、抱闸与速度限制仍需核对。

接下来先只读记录`6060`、RxPDO中该模式对象的NC/PLC链接，以及`3C04/05/06`。在支撑并受控停用后，才由实际负责PDO的主站程序调整模式请求和过渡；不能在未知目标和环参数下带使能试切模式。若模式请求恢复成8，先检查主站周期写入及Startup配置，也需核对驱动是否接受该模式，不能反复强写CoE。

即使以后`6061=-1`，也不能直接把当前607F增大作为“解锁”办法：手册说明超过该上限会进入内部速度控制，而其单位与电机/输出端坐标有关。应与已验证的关节速度和力矩限制一起设计。先完成模式和增益核对，再决定受控零力矩试验流程；本次没有下发切模式、使能或抱闸命令。
