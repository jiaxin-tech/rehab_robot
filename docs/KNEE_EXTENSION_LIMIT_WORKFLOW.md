## 三层限制各解决什么

1. **机械伸展止挡**：在真实伸直端阻止机构继续超伸，作为驱动失能、断电或参数失效时的实际边界。其结构、承载和缓冲需按真实夹具与机械臂外力确认。
2. **驱动软件位置上下限**：drive4使能、正确控制模式与坐标成立时，限制其运动指令/位置范围。手册描述超限后零速停车，仍保持使能，随后允许向范围内退回。
3. **主站目标限幅与协调**：TwinCAT生成的目标应在到达驱动极限之前收住，考虑制动距离、刷新延迟和标定误差；与机械臂的运动也必须兼容。

驱动未使能、抱闸强制打开而由外力拖动时，不能把软件位置上下限当成物理止挡。重新抱闸通常会限制双向运动，也不是允许正常屈伸的角度边界。

## 全闭环、力矩模式、抱闸、软限位分别是什么

“闭环”指传感器反馈环，“抱闸”是机械制动器；二者没有“解除抱闸就变成非全闭环”的关系。

| 项目 | 对应设置 | 实际作用 |
|---|---|---|
| 全闭环/非全闭环 | PrD.00 / 3D00 | 选择电机端或输出端相关的反馈与坐标；非全闭环仍可有电机端反馈，不等于开环或自由轴 |
| 位置/速度/力矩运行模式 | 6060请求、6061实际反馈 | 决定伺服主要跟踪哪个目标；厂家−1模式使用3C18目标及3C1A输出端力矩反馈 |
| 抱闸释放 | 正常使能时序；381E为强制开闸控制 | 解除机械制动，不会据此选择位置/力矩模式，也不直接选择3D00 |
| 软位置限位 | Pr8.09 / 3809与607D:01/02 | 在正确的活动控制状态与坐标下实施位置范围限制，不能代替未使能时的机械止挡 |

厂家−1模式的输出端“力矩闭环”，与PrD.00的“全闭环反馈方式”也不能混成一个开关。不能因为要输出端力矩为0，就直接认为PrD.00必须设成1；具体反馈配置应按模组编码器、固件及控制模式核对。

本次计划的正常工作组合是：drive4保持Operation enabled、6061=−1、机械抱闸按正常使能流程释放、力矩环目标为3C18=0、主站与驱动在实测有效的膝角范围内限制运动。手册6.6称软限位适用于EtherCAT各种模式，但TC600E具体固件在厂家−1模式下的边界行为仍需独立验证，并计入制动距离和机械止挡。

强制开闸本身不是“取消力矩控制”的模式选择，也不是与力矩模式天然互斥；是否主动控制，取决于驱动使能和实际运行模式。当前先用正常使能放闸实现工作状态，前述未使能强开只用于有支撑的机械诊断，不作为常规运动方案。失能后即使能手推，也没有电机主动执行位置边界。

目标为0Nm不保证无阻力手推；还需实际放闸、有效的力矩环、合适的速度限制和机械状态。尤其3D00已被修改并重启，应先核对新运行配置的位置单位与原点，再计算607D计数边界，不能继续把旧角度公式或角度数字直接当成驱动限位值。

## 第二步：复核真实伸直位置与计数方向

膝关节伸直定义为本次安装中大腿与小腿的机械参考对齐，不是把驱动当前计数直接当成0。先让膝驱动在有机械支撑、解除机械臂刚性牵制或采用已验证协调控制的条件下独立调试；不能让机械臂位置控制与膝位置控制互相顶住。

记录真实伸直附近参考的`0x6064`，记为`P0`；在已确认可手动/受控活动的范围内，核对小幅屈曲时计数是增加还是减少。顺/逆时针依观察侧而变，设置上下限以计数方向和实际屈伸为依据。

同一控制模式、编码器选择、原点偏移和单位下，取得每度对应的位置单位`C`。全闭环与非全闭环的单位不同：不能照抄手册81或101减速比例子，也不能直接把角度值0和120写入位置单位的607D。

现有仓库使用旧公式：

```text
theta_knee_deg = (axis4_position_raw + 2615016.5409129467) / 36794.035628458296
```

该旧扫描只覆盖0～60°，存在独立测角误差，不能作为“不反关节”的精确零位证明。当前配置`calibration.knee.safe_min_deg=-10`还允许软件计算的负角度；11月22日静止计数约−2896981，按旧式算为约−7.66°。这不证明实物已经超伸，也不能据此直接把某个旧计数写成伸直限位。

本次先记录与核实`P0`，不擅自写回零参数、改变原点偏移、翻转电机方向或重置多圈编码器；这些操作会影响已有坐标与主站目标。

## 第三步：算出边界，再设置驱动与主站

定义本次允许的最小屈曲角为`theta_min`，最大屈曲角为`theta_max`。伸直端应按实测停止距离、延迟和标定误差保留余量；驱动停车不是瞬间完成，不能把在精确0°才触发停车当作不会越界的保证。最大角度也需由真实安装核实，不默认沿用145°。

若已核实屈曲时计数增大：

```text
607D:01 = P0 + C * theta_min
607D:02 = P0 + C * theta_max
```

若屈曲时计数减小：

```text
607D:01 = P0 - C * theta_max
607D:02 = P0 - C * theta_min
```

结果使用驱动认可的有符号32位位置单位；取整应向允许范围内收紧，保证最小值小于最大值。`−2147483648 / 2147483647`这组默认极值表示软限位无效，不能当作已经开启了有效膝角限制。

在参数与主站控制审查完成后，按该驱动版本的流程设置`607D:01/02`并将`Pr8.09`置1，同时在主站限制目标。手册第6.6节称开关默认1，附录参数表又列0，因此必须读取实际值，不能依赖默认开启。若主站有启动SDO或NC软件限位，同步检查实际生效值与单位；保存/重启后的持久性按该设备流程确认并回读，不猜保存命令。

手册`Pr1.19 / 0x3113`为超程保护减速时间，示例默认50ms。这里不改其值，也不把50ms当成整套系统的已测停车时间。不要以单向力矩限制或方向翻转替代角度限位。

## 第四步：先验证边界功能，再做完整动作

最初在远离真实伸直端的小范围测试边界，以已确认的低速、有限力矩和正确目标同步核对：趋近边界时能停止，向范围内部仍能回退，实际位置与警告变化符合预期。先得到真实停止距离与坐标依据，再逐步确定伸直端边界；不通过主动超伸实物来验证软件是否有效。

手册第6.6节描述正/负限位触发时显示`-pot- / -not-`，错误码示例`0x0107 / 0x0108`；其他故障表还列有目标超限与实际超程的不同编码。因此现场记录真实模式、位置、目标、状态字和完整错误文本，不仅凭某个码猜行为，也不屏蔽错误检查让试验继续。

机械臂与小腿刚性连接时，后续必须采用几何兼容的位置/朝向与膝关节运动协调；原空载固定朝向轨迹不能因设置了膝软限位就直接恢复运行。

## 与当前代码的关系

当前配置和`lab_session._passive_leg_guard`按被动假腿编写，要求驱动未使能；drive4使能后会触发停止。这是协议不匹配，不能只改一个`expected_operation_enabled=true`就把主动方案当成已审核。

主动膝方案需要独立记录控制模式、目标生成与限幅、使能过渡、停止方式、设备限位回读和安装标定，再增加相应采集/守卫支持。主动膝输出也会改变机器人所测负荷，论文实验条件需明确区分。当前只读采集、90秒空载曲线和被动保护配置保留，不提供未审查的驱动写入或使能脚本。

## 现场问题：使能后把3C18设0，仍推不动

本次已确认实际模式`6061=8`，属于CSP位置控制，位置环会抵抗偏离目标位置的外力。`3C18=0`不解除位置环，`607F=10000`也只是速度上限，不会切换控制模式。机械臂已分开，当前没有它的刚性牵制。

协议第6.10节（PDF第33页，印刷26页）描述厂家输出端力矩闭环模式：请求模式`6060=-1`，目标为`3C18`（FLOAT，Nm），反馈为`3C1A`，使用`3C04/05/06`力矩环PID增益，并有`607F`速度限制。当前实际模式应以`6061`核实；有符号−1也可能以字节`0xFF`显示。

标准CST模式则是10，目标为6071，不能把两种力矩环的目标和单位混用。零电机转矩、零输出传感器转矩及可低阻力手推也不等同；减速机摩擦、环路参数、抱闸与速度限制仍需核对。

接下来先只读记录`6060`、RxPDO中该模式对象的NC/PLC链接，以及`3C04/05/06`。在支撑并受控停用后，才由实际负责PDO的主站程序调整模式请求和过渡；不能在未知目标和环参数下带使能试切模式。若模式请求恢复成8，先检查主站周期写入及Startup配置，也需核对驱动是否接受该模式，不能反复强写CoE。

即使以后`6061=-1`，也不能直接把当前607F增大作为“解锁”办法：手册说明超过该上限会进入内部速度控制，而其单位与电机/输出端坐标有关。应与已验证的关节速度和力矩限制一起设计。先完成模式和增益核对，再决定受控零力矩试验流程；本次没有下发切模式、使能或抱闸命令。

### 后续反馈：drive1可推，drive4仍不可推

操作者随后报告“6060和6060都设成−1”，第四轴实际位置`6064=-2981273`、位置目标`607A=-2827251`；机械臂已分开，手推drive1可动而drive4不可动。重复的6060不能作为实际反馈模式已确认的证据，下一步应只读刷新drive4的6061（该对象只读，不需设置）。

两位置值相差154022计数，但在已确认的−1输出端力矩模式下，607A并非主控制目标，不能把这个差值当成位置保持原因，也不据此改位置目标。

同一`607F=10000`可能在两轴形成不同的输出转速上限：只有当607F确实使用与旧标定相同的计数/秒单位时，髋约10.06°/秒、膝约0.272°/秒。这是核对限速的线索，不是已确认的当前速度值；`PrD.00`及反馈来源等会改变单位，不能直接按这个换算增大速度。

另一待核对项是新设的607D限位。如果当前位置落在软件范围外，手册描述驱动保持使能并零速停车，可能阻碍手推；需要实际上下限、Pr8.09、状态字和错误码来判断，不能通过关掉限位试图解锁。

最少只读回传项：drive4刷新后的`6061`、`6041`、`603F`、静止`3C1A`，以及是否修改过`607D:01/02`。据此区分未实际进入模式、未实际使能/抱闸、位置限位或速度限制，再按需要对比两轴`3D00/606C/607F`及力矩环参数；不加力硬推，不盲目提高限速或增益。

### 已进一步确认：6061=-1，6041=0x1237

操作者报告无错误，3C1A读数持续变化，随后提供6041为0x1237，并明确刷新后的只读6061为−1。0x1237中bit2为1，CiA402状态掩码`6041 & 0x006F = 0x0027`，属于Operation enabled；bit3（Fault）、bit7（Warning）、bit11（Internal limit active）、bit14（Torque limit active）均为0。该快照未显示这些标志触发，但不能证明所有模式内部的限速均未生效，也不直接证明抱闸已经机械释放。

bit12属于运行模式相关位；手册没有给厂家−1模式完整的专用位定义，不能用它或bit10直接判定零力矩目标已经达到。3C1A更新只表示反馈在读，不等于目标跟随已通过。当前已排除本次读数下“尚未使能”和“仍是8号位置模式”，不再用607A与6064的差值解释推不动。

下一项只读对照为drive1和drive4各自的6040控制字、3D00（PrD.00）选择值。控制字用于检查暂停指令；模式与单位差异用于核对同一607F的实际意义。手册标准速度/转矩模式表给出6040.bit8的Halt含义，厂家−1模式的具体适用行为仍需结合该固件确认，不能看到一个位就盲目改写整字。参数保持原状后再决定后续核对项。

### 反馈“31、0”及随后修改PrD.00

操作者对控制字/全闭环选择的询问回复“31 0”，当前暂按drive4的6040为十进制31、3D00为0理解，轴归属与进制还应核对。十进制31等于0x001F，6040.bit8未置；若31实际上为十六进制0x0031，则低位使能组合不同，不能混用解释。

随后操作者表示已将drive4的3D00改成与drive1一样的1，但未改善手推。此次读取请求本来只用于比较，不是全闭环切换方案；PrD.00是反馈方式选择，不是“允许拖动”开关。手册6.4要求修改后重启伺服，且全闭环将位置/速度参考改为输出端，因此写入1不证明当前运行配置已经切换，重启后也不能继续沿用旧计数标定与未经核对的软限位。

当前不据此继续改参数或建议重启。先确认此次修改后是否已重新上电，以及最新6064读数；确认实际运行坐标后，再安排受控停用下的参数处理。尚未取得3C04/05/06及3C0D的现场读数，不能断言力矩环增益或输出限幅有误，也不提供盲目增益调整值。

### 重启后状态、声音与抱闸对照

操作者确认已经重启，最新6064为−3038037；两轴均未手动强制开闸，drive1在enabling时有“咔嗒”声，drive4无明显声且无错误。随后再次只读确认drive4的6041=0x1237、6061=−1，因此重启后仍为已使能的厂家力矩模式。0x1008/型号反馈为TC600E，但该名称不包含实际关节模组的制动器配置。

手册第1.2节的完整模组型号在制动器配置位区分X（无制动器）与B（有制动器）。TC600E驱动名称及声音差异不能证明第四轴一定有抱闸或抱闸故障。第6.8节展示正常使能中的抱闸时序，未手动写381E=128不代表正常使能时未放闸；381E也是控制参数，不是抱闸机械开闭反馈。操作者当前读取381E为0。

**单次对照的前提**：机械臂已与小腿分开；小腿由支架或台面可靠支撑，解除保持力后不会坠落或越过伸直端；本机381E:00对象明确与该固件的Pr8.30/“强制抱闸打开”一致。对象不存在、含义不明或无法保持机械支撑时，不执行写入，先核对实物型号与本机文档。

按第6.7节进行以下有限对照，不在当前使能状态下强开：

1. 按已有原厂/主站正常流程停用drive4。只读刷新6041，确认Operation enabled位bit2为0后才继续；不能仅凭点击了停用判断。状态仍为0x1237时停在本步。
2. 保持支撑与未使能，向已经核对含义的381E:00写十进制128（UINT16），再读回值。只控制强制开闸，不更改3D00、速度、增益、位置零点或力矩目标，也不重新使能。
3. 观察释放情况，仅在正常屈曲方向以很轻、小范围的方式判断能否活动；不强推、不测试反关节方向。没有声音不能单独判故障，尤其制动器配置尚未核实。
4. 保持未使能和机械支撑，将381E强制开闸指令恢复为0；支撑不能因恢复指令就立即撤除。记录是否有声、是否能活动、381E读回和全过程6041，再决定后续主动控制测试。

如果未使能强开后可活动，说明该状态下机械链能够运动，应继续查使能后的力矩环、限速和抱闸控制差异，不能把128永久保留当作完整主动控制方案。如果仍不能活动，停止手推，核对是否确实带抱闸、实际释放链路、机械止挡与减速器阻力；此时不通过增大增益或力矩“顶开”。

本流程是操作者现场按厂家功能做的有限诊断说明；助手没有连接设备或下发任何控制命令。原采集程序仍按被动假腿约束编写，不替代主动关节的停止与协调控制。

### 对照结果与非零目标试验后的停止状态

操作者反馈：drive4未使能、按前述强制开闸对照后可以弯曲，一使能就不可手推。这只证明该未使能状态下机械链能够活动，不能直接排除使能时抱闸状态变化、限速或力矩环控制阻力。尚未取得“锁住当下”的6061/3C18/381E三项联合读回，不把主站覆盖或某个具体故障定为根因。

随后操作者表示把3C18目标改成100，drive4出现主动运动，且drive1也曾改同一对象。手册将3C18定义为FLOAT、单位Nm，所以100是非零的100Nm目标，不是百分比或拖动灵敏度；实际是否达到该目标由反馈与限幅决定，不能把写入值当成已测输出。只改变目标值也不能据此认定切换了模式，仍需6061反馈；一轴的同名目标与行为不能证明另一轴具有相同模式、使能、参数或实际输出。

助手立即提示停止手推、支撑假腿并按原厂流程停用两轴，停稳后将两轴3C18恢复0并读回，不再用非零大目标或手工对抗力矩排查。操作者已明确回复：“两轴已停用，3C18均读回0”。这里的0是力矩目标，不是关节位置回零；当前不重新使能。

下一次只读对照一次记录两轴3C04、3C05、3C06、3C0D、607F，分别检查力矩环增益、输出限幅和限速。这些实际值尚未回传，因此暂不建议复制另一轴参数、提高增益/力矩/速度上限，也不把能主动转动当成零力矩低阻力拖动已经通过。
