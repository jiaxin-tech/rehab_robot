# 下一次实验室操作手册：带假腿同会话采集与训练

版本日期：2026-10-19

本手册对应提交 `358ebb2` 及之后的代码。目标是完成一轮“假腿采集 + 机械臂参考轨迹 + 冻结算法训练”。本手册不授权绕过安全门禁，也不把软件演练结果当作真机结果。

## 先看结论

这次到实验室按下面顺序做：

1. 更新代码，保留实验室原始配置和数据。
2. 用新版包做离线检查。
3. 做安全事件、假腿采集、机器人状态和力数据的静止诊断。
4. 补齐并评审带假腿配置，重新生成当前代码绑定的发布。
5. 运行一轮带假腿参考轨迹。
6. 确认停止、下电、断开和 CSV 完整后，才允许训练。
7. 保存本轮报告，核对所有原始文件和哈希。

带假腿训练不使用空载 259 豁免。安全事件没有有效状态时，程序必须阻断。

## 一、到实验室前准备

需要带到实验室电脑的内容：

- 当前仓库代码，至少包含提交 `358ebb2`；
- `results/lab_next_visit_20261019_loaded.zip`；
- 当前实验室的安全配置、力采集配置、假腿配置和现场证据；
- 原始 CSV 和历史日志的备份。

压缩包是代码和离线验证交付包，不是安装器，也不是安全批准文件。解压后先比较文件，再把需要的源码合并到实验室当前版本。不要直接覆盖现场配置，不要删除原始数据。

## 二、更新代码并确认版本

在实验室电脑的仓库目录执行：

```powershell
git status --short
git log -1 --oneline
```

确认当前代码已经包含 `358ebb2 Add loaded same-session lab workflow`。如果实验室有未提交改动，先备份并记录，不要直接丢弃。

确认 Python 使用项目要求的 CPython 3.12：

```powershell
python --version
```

如果使用项目虚拟环境，后续命令中的 Python 替换为：

```powershell
.\.venv\Scripts\python.exe
```

## 三、建立本次运行目录

建议为本次访问建立独立目录，例如：

```powershell
$visit = "results/lab_visit_$(Get-Date -Format yyyyMMdd_HHmmss)"
New-Item -ItemType Directory -Force $visit | Out-Null
```

记录以下信息：操作者、审核人、机器人序列号、控制器版本、SDK 版本、假腿安装方式、当前工具和工件、当天配置文件哈希。

## 四、离线检查：只检查，不连接机器人

新版带假腿配置草稿位于：

```text
results/lab_next_visit_20261019_loaded/round_training_draft.json
```

使用该包的启动配置执行：

```powershell
.\results\lab_next_visit_20261019_loaded\StartLab.ps1 Check
```

或者在仓库根目录直接执行：

```powershell
python -X utf8 -m scripts.lab_session check `
  --profile results/lab_next_visit_20261019_loaded/launcher.json
```

检查结果会写入 `results/next_lab_visit/<时间>/blockers.json`。此时应重点检查：

- `reviewed`、`passed` 是否仍然真实反映现场评审状态；
- `collision_event_max_age_s` 是否已由现场评审确定；
- `allowed_operation_states` 是否明确包含 `rtcontrolling`；
- 假腿标定、时序和分析字段是否齐全；
- 当前角度标定范围是否覆盖参考轨迹；
- 安全配置是否包含当前软限位、起点容差、命令时限和 RT 参数；
- TwinCAT ADS DLL 是否存在且位数匹配。

只要仍有阻断，就停在这里补证据和配置。不要批量把 `reviewed` 或 `passed` 改成 `true`。

## 五、三项静止诊断

### 1. 安全事件诊断

```powershell
.\results\lab_next_visit_20261019_loaded\StartLab.ps1 Events -Live
```

确认报告中有：

- 初始安全事件状态；
- 事件序号或连续性信息；
- 当前状态为有效且无碰撞；
- 没有故障或断连；
- 结束时已确认断开。

回调没有消息不能解释成“没有碰撞”。如果初始状态未知或中途失效，不能继续带假腿运动。

### 2. 假腿采集诊断

```powershell
.\results\lab_next_visit_20261019_loaded\StartLab.ps1 Capture -Live
```

保持机械臂不运动，确认 CSV 能持续写入，时间戳递增，轴状态、原始计数和力矩字段存在，没有长间隔、重复时间戳或持续缺失。

### 3. 机器人状态和力数据诊断

```powershell
.\results\lab_next_visit_20261019_loaded\StartLab.ps1 Observe -Live
```

确认机器人身份、工具/工件、负载、软限位、状态流和力流都匹配当前评审配置。这个步骤是静止观测，不代表 RT 并发时序已经验证通过。

## 六、现场评审和发布

在运行参考轨迹前，由操作者和安全负责人共同核对：

- 运动范围内无人，急停可用；
- 假腿已正确固定，机械臂工具和工件正确；
- 负载参数与控制器当前配置一致；
- 当前机器人初始状态为可控的 `IDLE`；
- 安全事件初始状态有效且无碰撞；
- 参考轨迹覆盖的髋、膝角度都在已验证范围内；
- 轨迹起点、工作空间、软限位、速度和加速度符合评审配置；
- 状态/力数据新鲜度、对齐和写盘预算已经评审；
- 本次发布绑定的是当前代码和当前所有配置文件。

发布文件必须重新生成。旧发布文件不能因为“配置看起来没变”而继续使用，因为源码哈希已经变化。

## 七、运行一轮带假腿实验

配置和发布准备完成后执行：

```powershell
.\results\lab_next_visit_20261019_loaded\StartLab.ps1 Round -Live
```

程序会先获取当前位置并生成起点和轨迹预览。现场查看预览，确认没有明显越界、方向错误或起点错误后，输入完整确认语句：

```text
I CONFIRM REVIEWED ROBOT LEG ROUND
```

之后程序按以下顺序执行：

1. 校验当前发布和所有文件哈希；
2. 初始化冻结的残差 GP 均值 Greedy 算法；
3. 启动假腿 CSV 采集；
4. 在同一个 SDK 会话中准备 RT；
5. 再次检查身份、负载、软限位、碰撞状态、起点、状态/力新鲜度和写盘健康；
6. 通过最终门禁后才发送首条保持目标和参考轨迹；
7. 轨迹完成或发生故障时停止 RT、下电并断开；
8. 确认清理完成后关闭假腿采集；
9. 检查 CSV 和机器人记录；
10. 计算对齐指标并运行一轮冻结算法训练；
11. 写出本轮 `report.md`、`round_status.json` 和模型更新记录。

程序不会自动重试，不会自动发送下一候选轨迹。当前第一轮是参考轨迹初始化，结果中的归一化指标不代表优化有效。

## 八、运行过程中的停止条件

出现以下任一情况，立即按现场规程使用物理急停，并保留程序日志：

- 安全事件状态变为未知、碰撞或故障；
- 状态流或力流中断、过期或无法对齐；
- 起点偏离、负载或工具/工件不匹配；
- 假腿 CSV 长时间不增长或写盘失败；
- 运动范围、软限位、速度或加速度不符合预期；
- 任何人进入运动范围；
- 程序报告 `ROUND_FAILED`、清理失败或训练前置条件不满足。

不要为了继续运行而提高超时、放宽年龄阈值、接受未知碰撞状态或复用空载发布。

## 九、完成后核对文件

成功回合至少应有：

```text
round_status.json
report.md
release_approval.json
reviewed_anchor.json
trial_setup.json
leg/leg.csv
dispatch.csv
measured.csv
measured_metrics.json
training_request.json
model_update.json
```

只有同时满足以下条件，才把本轮记为训练完成：

- `round_status.json` 中 `status=ROUND_COMPLETE`；
- `training_status=MODEL_UPDATED`；
- 机器人清理状态已记录；
- 假腿 CSV 质量检查通过；
- 原始 CSV 和机器人记录哈希已保存。

如果状态是 `ROUND_FAILED` 或 `NOT_UPDATED`，保留全部原始文件和报告，不能把它改写成成功结果，也不要用失败数据训练。

## 十、把结果带回本机

将整个本次运行目录、原始 CSV、配置副本、现场评审记录和控制器日志一起带回。论文分析只使用通过质量检查的真实采集数据。

软件离线演练目录中的 CSV、模型和报告全部标记为合成数据，不能混入论文实验结果。

## 现场仍未验证的事项

- 安全事件初始状态和持续有效性；
- RT 并发下状态/力采集的实际时序；
- 当前安装的负载、工具、工件和软限位；
- 标定范围对参考轨迹的覆盖；
- SDK 停止、下电、断开后的实际机器人状态。

报告中的 `SDK_STOP_POWER_DOWN_DISCONNECT_COMPLETED` 只表示相关 SDK 调用返回成功，不等于独立的物理停止证明。
