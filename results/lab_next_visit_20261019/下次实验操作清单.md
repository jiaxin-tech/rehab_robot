## 2. 一条命令采诊断数据：无轨迹、无上电命令

确认网卡IP与launcher.json一致，按现场规则监督实际SDK会话：

```powershell
.\results\lab_next_visit_20261019\StartLab.ps1 Diagnostics -Live
```

程序按顺序完成：10秒安全事件观测、10秒假腿ADS采集和自动质量检查、10秒机器人状态与真实独立力进程采集。某一段失败仍执行其他独立诊断，全部保留日志；结束后总结果可能为失败，不会自动反复连接重试。

这些是分段静止诊断，不是同轮同步实验，也不进行训练。不能从静止曲线自动得出设备时延。Observe使用无运动的观测配置，不会上电或取得RT控制器；RT准备后的并发采集特性仍需在相应现场流程中验证，不能由idle诊断直接宣布通过。

只跑一项时用Events、Capture或Observe替代Diagnostics，仍需-Live。若安全事件始终没有初始状态，保留unknown，不用制造碰撞让它产生数据。

## 3. 限时空载：只有夹具，无假腿、无人，不训练

此路径保留原有固定132.335秒降速轨迹、SDK259限定观测豁免及其他门禁，不扩展到训练。

先核对launcher.json里empty_load的起点、参考、夹具配置及评审请求是否就是当次实际情况。旧起点仅在现场再次确认且实时位置满足容差时才适用；若安装/起点不同，按既有起点采集与评审流程重新制作，不能把当前姿态自动标为已评审。

```powershell
.\results\lab_next_visit_20261019\StartLab.ps1 Release
```

这一步不连接设备，会显示原范围完整确认文本。需要现场核对并实际输入，脚本不会自动读取并代填签认。生成的发布绑定当前代码与输入，最多30分钟且不会超过评审请求期限；不会覆盖旧发布。

取得终端打印目录下的release.json路径后：

```powershell
.\results\lab_next_visit_20261019\StartLab.ps1 Empty -Live -Release '本次生成的release.json完整路径'
```

先做离线发布核对，再提示确认实际运动。通过后才调用现有同会话实时准备、最终门禁、一次轨迹、清理链路。实时准备会改变模式/上电；这不是采集命令。任何门禁失败均不自动重试，不放宽阈值。领取后即使未下发目标，也不能自动复用同一发布。

时限表示发布有效窗口，不是“无条件允许运动30分钟”；轨迹仍是一周期132.335秒，超限或发布失效仍会停止。记录目录不等于物理停止已被证实，最终状态应按现场规则核对。

```powershell
.\results\lab_next_visit_20261019\StartLab.ps1 Round -Live
```

流程：完整配置检查 → 读取当前位置并生成起点/轨迹预览 → 现场核对预览后明确确认 → 冻结算法初始化 → 假腿预采集 → 一次经发布的参考运动与机器人采集 → 假腿后采集 → 质量与时序/跟踪检查 → 从真实CSV构建测量 → 更新残差GP均值Greedy → report.md。
