# 阶段 4.5A：wrench 时间对齐与延迟补偿审计

本审计只覆盖软件虚拟数据中的固定 wrench 延迟。它不验证真实患者参数，
不接入 ROKAE 控制、采集、安全或硬件代码，也不涉及模型失配、轨迹优化、
PINN、MPC 或触觉。

模型继续严格采用：

```text
theta_shank = q_hip - q_knee
```

## 1. 为什么时延主要影响阻尼参数

阻尼力矩与关节角速度成正比。wrench 延迟会把时刻 `t-delay` 的力错误地
配给时刻 `t` 的 `q`、`dq` 和 `ddq`，从而产生系统性的相位错位。屈曲与
伸展期间速度会换符号，错位后的残差最容易被优化器错误解释为阻尼变化。
质量缩放也会受加速度相位影响，但当前多 family、多速度激励为质量、刚度
和阻尼提供了额外区分信息。

## 2. 为什么普通力噪声通常小于时间错位的影响

本项目的零均值独立力噪声主要增加逐样本散布；足够多样本和稳健损失可以
部分平均这种扰动。固定延迟则会沿整条轨迹一致地改变力与运动状态的对应
关系，形成与速度、加速度相关的结构化误差，不能靠增加样本自动平均掉。
这只是当前虚拟数据模型中的观察，不应外推为所有真实传感器。

## 3. 精确恢复不代表真实系统

固定延迟仿真使用同一软件时钟、已知平滑动力学、无时钟漂移、无时间戳
量化误差，并且训练/验证轨迹有充分激励。真实系统可能同时存在抖动、漂移、
丢包、滤波群延迟、线程调度延迟、wrench 坐标系误差和模型失配。因此，
虚拟数据上恢复 16 ms 或 32 ms 只能验证算法链路和符号，不能证明真实
机器人上会得到同样结果。

## 4. 1 ms 搜索步长的分辨率限制

自动估计只在 `[-50, +50] ms` 的 1 ms 网格上选择候选。非整数延迟会落到
验证 RMSE 最低的邻近网格点，量化误差通常不超过约 0.5 ms，但噪声、有限
采样和模型误差可使结果偏移到相邻点。因此不报告亚毫秒精度，也不把网格
点命中解释为连续时间精确值。

## 5. 超出 ±50 ms 的处理

如果最优候选位于 `-50 ms` 或 `+50 ms`，结果设置：

```text
search_boundary_hit = true
search_warning = selected_search_boundary_possible_out_of_search_range
```

边界值不是“精确估计成功”。它表示数据更偏好搜索端点，真实延迟可能位于
范围外；需要扩大离线搜索范围或检查时间戳，而不能静默把端点当作真值。

## 6. `offline_only` 不能直接用于在线控制

`offline_only` 使用目标时刻前后的有效 wrench 样本进行双向线性插值，
因此可能使用未来才到达的数据。它适合离线数据校正、算法评估和参数辨识，
不能直接放入实时控制环，也不能据此声明满足真实机器人实时性或安全要求。

## 7. `causal_history` 与 `offline_only`

- `offline_only`：允许前后样本，线性插值，不外推；输出
  `alignment_used_future` 和 `alignment_future_lookahead_s`。
- `causal_history`：只使用状态时刻已经到达的当前或历史 wrench，以最近
  历史值保持；所有有效输出都保证所用 wrench 到达时间不晚于状态时刻。

因果模式无法凭空“提前”尚未到达的滞后 wrench，通常比离线双向插值误差
更大。两种模式必须分别报告，不能互换结论。

## 8. 为什么不跨越超过 20 ms 的缺口

插值跨度越长，越可能跨过真实快速变化、dropout 或 stale freeze。当前
最大间隔为 20 ms：100 Hz 下单个缺失点的两个有效邻点相距恰好 20 ms，
可以被显式插值；连续缺失造成 30 ms 或更长跨度时必须保持无效。
`wrench_is_stale=True` 的有限数值不能作为新鲜插值端点，约 200–250 ms
冻结区间不能被静默填补。

## 9. 轨迹与激励对估计的影响

延迟可辨识性依赖轨迹中的速度、加速度、屈曲/伸展换向及髋膝独立激励。
近静止或单一低速轨迹可能让多个候选延迟的验证 RMSE 很接近。当前结果
依赖 coupled、hip-dominant、knee-dominant 以及多速度轨迹，不代表任意
临床轨迹都能稳定估计延迟。

## 10. 泄漏与数据边界

自动估计器：

- 只接受 train 和 validation 两个 DataFrame；
- 函数签名不接受 test 或 true delay；
- 使用观测字段白名单，并删除 `wrench_age_s`、旧 `wrench_delay_s`、
  `noise_scenario`、`subject_id`、真值力矩字段和 DataFrame attrs；
- 每个候选只在 train 拟合五参数，只用 validation torque RMSE 选点；
- test 只在延迟已经选定后做最终评价；
- 搜索曲线不保存 true delay 或 test 指标。

`wrench_age_s` 仍保存在完整虚拟数据中供最终审计，但不会进入自动搜索。
固定延迟真值只在自动选择结束后用于计算误差和“已知真值补偿”对照。

## 结论边界

阶段 4.5A 只证明：在当前二维虚拟受试者、正确动力学模型和固定延迟条件
下，离线 train/validation 网格搜索可以估计并补偿 wrench 时间错位。它
不证明对真实患者、真实 ROKAE SDK、在线控制、机器人安全或变化延迟有效。
