## 力从哪里来

旧机械腿和本次肌骨模型均由指定 q/dq/ddq 计算所需外部驱动力矩，并非预先给每条轨迹填写一个力值。旧模型用质量、惯量、重力、被动刚度/阻尼和耦合项；MyoLeg 保留原肌肉/肌腱模型及膝关节耦合约束，使用完整动力学分解并以 T(q)^T 投影到独立髋/膝坐标。

MyoLeg 零激活不等于肌肉/肌腱无张力，所导出的 actuator force 是该被动条件下模型的肌腱传递力，不能解释成主动招募肌力。轨迹 kinematics 本身不能唯一确定主动激活方案。本次也未模拟真实绑带接触力、机器人末端六维力或人体关节接触力。N m 的关节驱动力矩与 N 的肌肉力必须分开使用。

## 为什么旧 E2 会偏好参考

E2=max(RMS_Hf/RMS_Hf_ref, RMS_He/RMS_He_ref, RMS_Kf/RMS_Kf_ref, RMS_Ke/RMS_Ke_ref)。Reference 必为 1，但不必为最小值。要严格小于 1，四项都必须下降；只改善部分关节/阶段可能被另外一项上升抵消。

旧 Leg 0 在 (-0.03,+0.03) 下，四项相对量分别约为 1.000259、1.000745、0.990916、0.985255。膝两项下降而髋两项上升，故 E2=1.000745，比 reference 差。旧五腿逐项统计仍是前四腿没有 E2<1 的候选，第五腿有 144 个。这是冻结网格枚举结果，不是优化器自身宣告 reference 最优。

这一目标体现最坏相对分量的折中，而非总受力最小。代码算式自洽不代表参数已获实验验证，也不代表这一目标充分对应康复需求。更换模型后 optimum 改变亦不能单独证明旧实现有错误。

## 导出文件与验证

- trajectory_loads.csv：625 行，逐轨迹 E0/E2、四项原始 RMS、相对量、髋膝峰值、动力学项与约束项峰值。
- muscle_loads.csv：625×80=50,000 行，逐轨迹逐肌肉被动条件下力 RMS 和绝对峰值（N）。
- trajectory_torques_and_muscle_loads.npz：全部 625×401×2 力矩时序（N m）、时间、beta、肌肉名称和载荷矩阵。数组第一轴顺序与 CSV 一致，reference 在第一行。
- loads_and_landscapes.png：E0/E2 全域及参考/最优力矩曲线。
- summary.json：模型、ROM、参考及网格最优结果。

全 625 条零 MuJoCo warnings；逐采样动力学分解残差最大 1.07e-14 N m。导出后全部时序重新计算 E0/E2 与 CSV 一致。该检查验证数值与导出一致性，不验证人体真实性。
